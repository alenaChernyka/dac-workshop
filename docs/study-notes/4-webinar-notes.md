# SSG и настройка CI/CD  CI/CD  

## Плагины для mkdocs 

- сторонние
- встроенные

### Внутренние плагины

**Теги**

1. Прописать в yml файле.

```yaml
plugins:
	search
	tags:
		tags_allowed:
		- портфолио
		- manuals
		- rules
		- helps
		   
```

2. Добавить тег (над заголовком).

```
---
tags:
	- портфолио
	- manuals
---
```

3. Добавить страницы с тегами:

    - Добавить страницу с тегами md.

    ```markdown
    <!-- material/tags -->
    ```

    - Добавить все ссылки с нужным тегом

    ```markdown
    <!-- material/tags {include manuals}-->
    ```

    - Добавить все страницы кроме определенного тега

    ```markdown
    <!-- material/tags {exclude manuals}-->
    ```

### Внешние плагины

1. Скачать внешний плагин.

```bash
pip install mkdocs-glightbox
```

2. Прописать в плагинах.

```yaml
plugins:
	search
	tags:
		tags_allowed:
		- портфолио
		- manuals
		- rules
		- helps
	glightbox	   
```

## Публикация

### Обычная публикация

```bash
mkdocs gh-deploy
```

Создается папка site, пулл реквест и ветка gh pages (можно посмотреть в actions на гитхабе).

Папку site можно удалить.

### Автоматическая публикация

1. Создать workflow в Github Actions (сервис для автоматизации задач). Workflow — автоматизированный процесс.

2. Создать ветку, перейти в корневую папку проекта и создать новую папку ".github", в ней папку "workflows" и файл "ci.yml".

3. Добавить workflow в ci.yml. В офдокументации mkdocs есть готовый шаблон для воркфлоу (добавить установку внешних плагинов). 

    Сборка будет происходить на виртуальной машине, папки site уже не будет локально.

5. Закоммитить добавление воркфлоу, сделать пулл реквест и мердж.

6. Посмотреть в actions.
