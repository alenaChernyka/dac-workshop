# Что такое Docs as code

## Базовые понятия

Гибкий подход, который подстраивается под конкретные команды и проекты.

Docs as code — подход к разработке документации, основанный на принципах и практиках работы с кодом.

Документация как программный продукт — система, в которую входят процессы, наборы инструментов. Есть бэкенд: технологии под капотом системы, которая помогает писать и отправлять документацию. Есть фронтенд: клиентская часть, которую видят пользователи  — док портал в виде статического html сайтов (не всегда так, но часто).

Цель подхода — создание, развитие и поддержка актуальной, масштабируемой, многопользовательской системы документации и прозрачных процессов вокруг нее. 

## Практики и инструменты

Содержание (практики) и формы (инструменты)

### Унификация текста

1. Использование стайлгайдов, ред. политики и т.д.
2. Использование шаблонов
3. Переиспользование контента — единый источник
4. Унификация верстки текста — языки разметки

Язык разметки — это язык, предназначенный для форматирования и структурирования текста с помощью комбинаций разных символов. 

Облегченный язык разметки — язык разметки с простым синтаксисом, который удобно редактировать и читать в исходном виде.

### Версионирование и командная работа

Система контроля версий — программное обеспечение для работы с регулярно обновляющимися данными, которое позволяет хранить несколько версий одного и того же файла и отслеживать его изменения.

- Локальные
- Централизованные (на удаленном сервере)
- Распределенные (одновременно на разных устройствах)

Git — распределенная система контроля версий. 

Github, Gitlab, Gitverse — web-сервисы для хранения и управления репозиториями.

## Ревью документации

- Формализация процесса вычитки текстов
- Организация кросс-ревью
- Использование функциональности Github (комментирование и PR, апрувы)

### Сборка, тестирование и публикация документации. CI/CD

Генератор статических сайтов — инструмент, который автоматический конвертирует исходные текстовые файлы в html-страницы.

CI/CD — набор практик и инструментов для автоматического тестирования и развертывания приложений.

**CI (continuous integration) — непрерывная интеграция** 

Тестирование документации. Если ревью проверяет текст, то тестирование проверяет документационный продукт (например, ссылки) например, с помощью автоматического линтера. Генератор статических сайтов сам может тестировать. 

**CD (continuous delivery/deployment) — непрерывная доставка/развертывания**

Публикация документации на сервере внутреннем или внешнем. 

Непрерывный — значит запускается автоматически, когда есть изменения. 

Есть встроенные инструменты у гит-сервисов: Github Actions и Github Pages.

## Жизненный цикл документа

Путь документа от постановки задачи до публикации

Создание новой версии документа → Ревью документа → Обновление основной версии документа → Генерация документации → Публикация документа → Сборка и публикация → Создание новой версии документа (закольцованный)

## Преимущества подхода

- Хранение документации рядом с кодом
- Интеграция релизов документации  с релизом продукта
- Совместная работа с документацией
- Прозрачный процесс документирования

## Недостатки

- Дорогой и сложный (неоправданно для внутренней небольшой документации)
- Выше порог входа
